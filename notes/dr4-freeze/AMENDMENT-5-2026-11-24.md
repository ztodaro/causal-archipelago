# DR4 freeze, Amendment 5 (24 November 2026)

Recorded before Gaia DR4, which ESA plans to release on 2 December 2026. The stamped files and Amendment 4 stay as they were. This amendment does three things. It timestamps Amendment 4 with an independent check of its fix. It declares one rule that closes the J1749 follow-up on DR4. It withdraws E10b from DR4 scoring. It changes no prediction in B1, B2 or B4.

## 1. A timestamp for Amendment 4, with an independent check

Amendment 4 (19 October 2026) was published but never stamped. `AMENDMENT-5-SHA256.txt` lists the SHA-256 of the files below, and its OpenTimestamps proof anchors them before DR4:

- `notes/dr4-freeze/AMENDMENT-4-2026-10-19.md`
- `notes/dr4-freeze/e2b_perspective_v2.py`
- `notes/dr4-freeze/e2b_perspective_v2_check.json`
- `tests/test_perspective_sign_analytic.py`
- `notes/dr4-freeze/AMENDMENT-5-2026-11-24.md` (this file)
- `notes/dr4-freeze/j1749-target.tsv`

`tests/test_perspective_sign_analytic.py` checks `e2b_perspective_v2.py` against astropy. Two stars share one space velocity, or differ by a known small one. Astropy places the second star and reports each star's proper motion, radial velocity, separation and position angle. The fixed functions must recover the true relative velocity from those numbers. The test does not call or copy the stamped self-test, the check inside `e2b_perspective_v2.py`, or their helper functions. It reads the stamped `correct_perspective()` from the stamped file itself, after confirming that file's SHA-256 (`cfb446cc…`).

Results on 24 November 2026, from `python -m pytest tests/test_perspective_sign_analytic.py -v` (Python 3.13.18, NumPy 2.5.3, Astropy 8.0.3, pytest 9.1.1):

- All 7 tests pass. The main set has 1,500 pairs anywhere on the sky, at separations from 0.00001 to 0.005 rad.
- Both fixed methods leave no more than θ²|v|, the size of a second-order term. For separations up to 0.001 rad, the first-order fix leaves under 0.0001 km/s.
- The exact method `relative_tangential()` recovers a known extra velocity Δv (0.5 km/s per component) given to one star, to within θ²|v| + θ|Δv|.
- The stamped function doubles the term: its median error is 2 × v_r × θ, to within 2%.
- Applying the first-order fix to raw per-star east/north components leaves an error of the first order. Far from the equator its median is above 0.2 × θ × |v|. This confirms Amendment 4's warning.

The test was also run against two copies of the fix with a defect planted in each. It caught both. With the old sign put back into `correct_perspective()`, 1 test fails. With `relative_tangential()` reduced to a raw component difference, which ignores each star's own east/north basis, 3 tests fail.

Rerunning `e2b_perspective_v2.py` on the same machine gives `passes: true`. Every number matches `e2b_perspective_v2_check.json` to 10 significant figures (largest relative difference 2.5 × 10⁻¹¹). The bytes differ, because the published file has Windows line endings and four values differ in their last digits. The hash in `AMENDMENT-5-SHA256.txt` is of the published file.

Independence: the geometry comes from astropy, whose coordinate transforms were written by others and share no code with `e2b_perspective_v2.py`. The test itself was written by Claude (Anthropic), a model from the same family as the author of `e2b_perspective_v2.py`. It is a check by a different method, not by a different author.

## 2. J1749: one target and its closing rule

J1749 (LAMOST J174910.71+273448.1, Gaia DR3 4595936858688035968) is already a B1 target, on line 14 of the stamped `notes/novelty-search/r3-predictions.csv`. That row gives the Crius 227 anchor prediction, −24.2356 km/s, and the star's Gaia DR3 radial velocity, −23.51 ± 1.79 km/s.

`j1749-target.tsv` restates this one star in one row, with its earlier LAMOST velocity, and adds no target. Every target in the 1 September bundle stays as stamped, and B1's cohort count is unchanged. The rule below is a separate call for this star alone. It does not feed the B1 count.

The DR3 velocity already lies 0.72 km/s from the prediction. A "consistent" call on DR4 would confirm that at higher precision. It would not be the prediction's first independent test. For this star, DR4 adds mainly the binary screen and the epoch velocities.

### Identity

Gaia DR4 source identifiers are not DR3's, and ESA says to treat the DR4 source list as independent of DR3. The DR4 counterpart is the source in `dr3_neighbourhood` with `dr3_source_id = 4595936858688035968` and `probable_match = true`. If there is not exactly one such source, the call is Unresolved.

### What is pulled

For that source:

- `gaia_source`: `parallax`, `pmra`, `pmdec`, `ruwe`, `radial_velocity`, `radial_velocity_error`, `radial_velocity_origin`, `astrometry_origin`
- `all_source_flags`: `non_single_star`. The draft DR4 data model of 26 June 2026 puts this flag here, not in `gaia_source`.
- `spurious_signal`: the source's row
- epoch RVS, if published: `rvs_epoch_parameters_single` through DataLink, keeping `radial_velocity` and `radial_velocity_error` for transits with `rv_validity_flag = true`

Definitions. ΔRV = |`radial_velocity` − (−24.2356)| km/s. Epoch RV RMS is the root-mean-square deviation of the valid epoch velocities about their unweighted mean. It counts as published only with at least two valid epochs.

### The call

The conditions are checked in this order, and the first that holds decides:

1. **Unresolved:** not exactly one DR4 counterpart.
2. **Binary, blend or kinematic non-member:** a non-null `non_single_star ≠ 0`, or epoch RV RMS > 5.0 km/s, or ΔRV > 5.0 km/s.
3. **Unresolved in DR4:** no `radial_velocity`, or 3.0 < ΔRV ≤ 5.0 km/s.
4. **Consistent single-star Crius 227 kinematic candidate:** ΔRV ≤ 3.0 km/s, `non_single_star = 0`, and, if epoch RVS is published, epoch RV RMS < 3.0 km/s.
5. **Unresolved:** anything else, for example ΔRV ≤ 3.0 km/s with an epoch RV RMS from 3.0 to 5.0 km/s.

Parallax, proper motion, `ruwe`, `radial_velocity_error`, both origin fields and the `spurious_signal` row are reported beside the call, but they do not decide it. `spurious_signal` holds statistics, not a flag, and this amendment sets no threshold on them.

The call covers kinematics and binarity only. It never claims a calibrated age, lithium, a membership probability or youth. Whichever way it falls, it is reported.

### Archive conventions

DR4 pulls follow the conventions of Gaia ESA Archive release 3.15 (14 October 2026). That release renamed the DataLink data structures: `RAW` became `DATAMODEL_GAIA` and `INDIVIDUAL` became `DATAMODEL_STANDARD`. Queries run as asynchronous TAP jobs within the Archive's published limits. Pulls of several stars use uploaded identifier tables.

Table and column names follow the draft DR4 data model. If the released data model renames one, the column with the same documented meaning is used, and the change is reported.

## 3. E10b

E10b is withdrawn from prospective DR4 scoring: its joint-marginalization error was fixed only as a point refit (`E10B-CORRECTION-2026-10-19.md`), not in the stamped code or its intervals. B3's numerical purity prediction, which takes f from E10b, is therefore not scored; B3's directional predictions from E1c are unaffected.
